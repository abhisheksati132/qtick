How QTick works — the full picture

The problem (30 seconds)

An OS shares the CPU by giving each program a short turn — the time slice. Classic Round Robin fixes one slice for everything. Too short → the CPU wastes time switching programs. Too long → quick tasks get stuck behind long ones. No single length fits every workload, and the OS can't see the future.

Our solution — two AI agents

  • Agent 1 (quantum tuner): watches the queue — average remaining work, how mixed programs are, queue length, recent switch cost, recent preemptions — and picks a slice from {1, 2, 4, 8, 16, 32, 64}. Tabular Q-learning and a DQN (neural net, continuous state) both implemented; DQN wins held-out tests.
  • Agent 2 (dispatcher): watches each program's history via a neural burst predictor and picks who runs next from 4 rules (first-come / shortest-predicted / longest-waiting / I/O-first).
  • Reward: +3 for finishing inside the slice, −1 per switch, −0.03 × overshoot past the shortest waiting job. Context-switch cost is an explicit term, not an afterthought.
  • Safety wrapper: vetoes unsure decisions, clamps slices to [2, 64], forces longer slices when switching gets excessive — the same guardrails a real kernel deployment would need.

Key terms

Round Robin
Everyone takes turns with the same slice length.
Context switch (δ)
Cost of pausing one program and resuming another — saving state, refilling cache.
CPU-bound vs I/O-bound
Long calculators vs programs that frequently pause for input/output.
Q-learning / DQN
AI that learns by trial and error; DQN uses a neural net so it handles continuous measurements without buckets.
SJF / SRTF
Textbook algorithms that need to know the future — included only as an upper bound.
Composite / total score
Waiting + total time + switch penalty. Lowest wins.

What happens in one scheduling decision (6 steps)

  1. Observe. Snapshot: average remaining work, queue mix, queue length, recent switch-cost ratio, preemption rate.
  2. Pick who runs. Dispatch agent scores 4 rules using the burst predictor's per-program estimates.
  3. Pick how long. Quantum agent picks a slice from {1, 2, 4, 8, 16, 32, 64}.
  4. Safety check. Wrapper vetoes unsure picks, clamps to [2, 64], forces longer slices if switches spike.
  5. Execute & measure. Core runs min(q, remaining); δ charged on switches; waiting accrued; timeline logged.
  6. Learn. Reward = +3 finish in-slice, −1 per switch, −0.03 × overshoot. Stored in replay; networks update.
